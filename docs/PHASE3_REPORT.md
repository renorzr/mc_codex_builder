## 审批与执行边界

模型继续使用 Phase 2 的八个读取工具，通过 app-server `outputSchema` 输出可校验的具体整数坐标填充计划。纯文字回复可返回 `plan:null`。只允许主世界、附近小范围和静态整方块材料，不接受任意工具名、命令、方块状态或 NBT。

Gateway 在完整读取目标包围区后，按最终赋值去重重叠操作，计算实际改变格数与非空气覆盖格数。默认不覆盖非空气方块。审批摘要包含世界 ID、维度、坐标、材料、实际数量、执行批次、计划指纹和截止时间；完整操作清单保存到忽略提交的 `.local/plans/` 供查看。

审批绑定当前任务、客户端会话、MCPFabric 返回的世界 ID、维度、内存计划与区域状态。默认 120 秒内确认，仅使用一次。修改公开快照或磁盘计划文件不改变执行内容。待审批占据串行队列；拒绝、取消、过期或切换世界会结束旧计划。

写入由 Gateway 固定执行器调用上游 `set_block` / `fill_blocks`，而非让模型自由选择动作。写入 Thread 与模型规划 Thread 分离，写入 Thread 只接收诊断 RPC、从不运行模型回合。每个最终位置最多写一次，执行采用不重叠行批次；出错即停止，不重试已失败或结果未知的批次。

确认后先复查世界与完整原状态，每批前复查上下文及该批原状态；每批后读回，最终校验所有目标格及包围区其余格。完成后读取截图，并让只读模型结合图片说明视觉证据及局限。取消或异常可能留下已生效部分，不自动回滚。

## 上游依据与配置前提

使用固定 MCPFabric commit `a49a10641af2da813bb965e09114f7052c25ab35`，实际检查了 `tools.ts`、`WorldHandlers.java`、`CommandRunner.java`、`SessionScreenHandlers.java` 等源码：

- 单方块参数为 `x/y/z/blockId/dimension`，填充参数为 `from/to/blockId/dimension`。
- 写结果必须有 `success:true`，之后仍需读取方块确认。
- 区域请求使用 `includeAir:true`、`includeState:true`，拒绝截断、重复坐标、边界外坐标和缺失方块。上游会跳过未加载 chunk，因此只看 `truncated:false` 不足以证明完整读取。
- `get_screen` 提供 `inWorld` 和 `lastWorldId`，当前上游需要 `enablePlayerControl=true` 才可读取。此阶段因此要求该游戏门和 `enableWorldWrite=true`；Gateway 的工具白名单不包含移动、导航或命令。

Codex 的结构化输出参数依据[官方 app-server 文档](https://learn.chatgpt.com/docs/app-server)，类型继续沿用本机 0.167.0 生成结果。没有关闭 Codex 沙箱或自动接受工具审批。

## 已知限制

1. 首版只支持主世界的小型静态整方块建筑，默认包围体积/目标数 ≤2048、各轴距离 ≤32，最多 64 个模型填充操作和 256 个实际行批次。可配置上限最多 4096 格。不支持空气清除、NBT、容器、重力、液体、红石或任意命令。
2. 默认仅空气可改；若手工开启 `allowOverwrite`，仍会在摘要中显示非空气覆盖数，并要求本次确认。
3. 世界 ID 来自 MCPFabric 的当前 `sp:` 标识，客户端 nonce 仅做会话隔离，不能单独作为写权限。多游戏实例不受支持。
4. 上游读、写是分开的 RPC，不是比较后原子写入。检查与写入仍存在竞态，无法承诺任意外部并发修改时绝无误写。请使用独立测试世界验收，不应把它视为事务或可靠撤销系统。
5. 取消、网络丢失或超时可能发生在批次已生效但尚未读回时；报告区分已验证数量与当前批次不确定结果，后续批次不再发送，不自动回滚或重试。
6. 审批与执行状态不跨 Gateway 重启恢复；保存的 JSON 文件是审核副本，不是可重放的执行凭据。计划记录暂不自动轮换清理。
7. 真实游戏中的权限门、默认方块状态、chunk、原生命令限制、图片以及 Windows 执行流程仍需逐项验收，不能由模拟测试替代。
