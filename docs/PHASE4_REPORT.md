## 实现

- `!codex history [1-50]`：默认显示 10 条最近任务的只读元数据，跨世界和 Gateway 重启保留；不恢复审批、正文、Thread、命令回执或任务队列。
- `.local/history/tasks.jsonl`：默认每文件 1 MiB、共 3 个文件，内存最近任务索引 200 条；只保存编号、状态、时间、是否进入建造阶段和可选建造数量/指纹，不保存提示词、回复、原始异常、工具内容或 token。
- 重启将保留记录中未结束的任务标为 `INTERRUPTED`，不自动重试。当前文件未换行的尾部可修复；完整行损坏或归档不完整时明确阻止启动。运行中写入故障通过认证 `/health` 的 `history.healthy=false` 和历史命令显式报告。
- 初始化、配置读取、Thread 创建/恢复和世界预检期间取消，会关闭并等待子进程退出；模型回合保留原有中断流程。Thread 恢复被拒绝后，当前任务失败，后续新命令能创建新 Thread。
- Codex 进程在等待审批时退出，会结束该计划，后续建造必须重新生成并确认。保留默认审批不过期、可省略 task-id 和建筑配置的 15 分钟模型超时。
- Gateway 关闭停止接受连接、关闭 WebSocket 和未完成 HTTP 连接，取消任务并等待后端退出；重复关闭共享同一清理流程。
- Java 客户端增加 5 秒注册响应超时；文本发送串行，最多积压 16 条。重连、换世界后不重放指令，旧连接回调不能进入新连接。

配置和运行说明见 [开发说明](development.md#任务历史与重启phase-4)，通信语义见 [协议](protocol.md)。

## 保留边界

1. 日志是有保留上限的元数据历史，不能恢复结果正文或逐批证明世界状态。`BUILDING` 表示进入执行阶段，不代表方块必然已写入。崩溃时可能已有部分写入，必须检查世界，不自动回滚或重放。
2. 每个 dataDir 只支持一个 Gateway 写入，不含多进程文件锁。追加执行 flush，但日志轮换涉及多个文件，不是原子事务或完整审计保证。磁盘保留范围外的任务不能查询。
3. 历史日志和 `.local/plans/` 审核副本独立；计划副本仍不自动清理，不能用它确认旧计划。自定义 dataDir 必须自行排除 Git。
4. Windows 进程树清理沿用此前已验收的实现；本阶段新增的启动取消、重连与注册超时尚未在 Windows/Minecraft 内人工验证。Linux Java 传输烟测不覆盖 HUD 和真实游戏事件时序。
